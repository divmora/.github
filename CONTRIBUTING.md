# Contributing to DIVMORA Projects

Welcome to the **DIVMORA Technologies** open source and source-available community! We are excited to collaborate with you.

---

## Code of Conduct

All contributors and participants are expected to adhere to our [Code of Conduct](CODE_OF_CONDUCT.md).

---

## Conventional Commits & Pull Request Titles

Divmora uses [Release Please](https://github.com/googleapis/release-please) for automated semantic versioning and changelog generation. **All Pull Request titles and commit messages must strictly adhere to the Conventional Commits specification.**

### Common Types:
- `feat:` A new feature or major enhancement (minor version bump)
- `fix:` A bug fix or patch (patch version bump)
- `docs:` Documentation improvements or updates
- `refactor:` Code changes without functional or API modification
- `test:` Adding or updating automated tests
- `chore:` Maintenance, dependencies, tooling, or CI updates

---

## Pull Request Guidelines

1. **Fork and Branch:** Create a feature branch from `main` with a clear name (e.g. `feat/my-feature`, `fix/issue-123`).
2. **Local Validation:** Ensure all unit tests, linters, and build commands pass locally.
3. **Descriptive PR:** Fill out the Pull Request template completely, linking any relevant issues.
4. **CI Checks:** Ensure all automated status checks pass.

---

## Security Issues

If you discover a security vulnerability, please **do not** open a public issue. Follow our [Security Policy](SECURITY.md) to report it privately to `security@divmora.com`.
